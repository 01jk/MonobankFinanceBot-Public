# Дизайн-спецификация: Telegram-бот учета финансов Monobank

## 1. Обзор проекта
**Telegram-бот учета финансов Monobank** — это персональный финансовый помощник, интегрированный с официальным **Monobank Personal API**. Бот автоматически получает транзакции через защищенный Webhook (с возможностью ручной синхронизации через REST API), категоризирует расходы по MCC-кодам и пользовательским категориям, помечает внутренние переводы и формирует финансовую отчетность в реальном времени (Чистый денежный поток / Cash Flow, Совокупный доход, Совокупный расход, Аналитика по категориям, Среднесуточный расход, Суммарный баланс всех счетов).

---

## 2. Стек технологий и зависимости

- **Язык программирования**: Python 3.11+
- **Фреймворк Telegram**: `aiogram 3.x` (Асинхронный фреймворк для взаимодействия с Telegram Bot API)
- **Веб-сервер / HTTP-клиент**: `aiohttp` (для отправки запросов в Monobank API и приема входящих Webhook от Monobank)
- **База данных и ORM**: `SQLite` через `SQLAlchemy 2.0` (Async Engine) + `aiosqlite`
- **Развертывание и среда**: Docker / Railway (`PORT`, `WEBHOOK_BASE_URL`, `WEBHOOK_SECRET`)
- **Валидация и сериализация данных**: `pydantic v2`

## 3. Схема базы данных (SQLite через SQLAlchemy 2.0 Async)

### 3.1. Таблицы

#### `users` (Пользователи)
- `id` (INTEGER, PK) — Telegram ID пользователя.
- `mono_token` (STRING, Nullable) — Персональный токен Monobank API.
- `webhook_secret` (STRING, Unique) — Секретный токен уникального пути для проверки Webhook.
- `is_admin` (BOOLEAN, Default False) — Флаг администратора.
- `created_at` (DATETIME, UTC) — Дата регистрации.

#### `accounts` (Счета и карты)
- `id` (STRING, PK) — Идентификатор счета из Monobank (`account_id`).
- `user_id` (INTEGER, FK -> users.id) — Telegram ID владельца.
- `type` (STRING) — Тип карты/счета (`black`, `white`, `fop`, `jar`).
- `currency_code` (INTEGER) — Код валюты (980 = UAH, 840 = USD, 978 = EUR).
- `balance` (INTEGER) — Баланс в копейках.
- `credit_limit` (INTEGER) — Кредитный лимит в копейках.
- `masked_pan` (STRING, Nullable) — Маскированный номер карты.
- `iban` (STRING, Nullable) — IBAN счета.
- `is_active` (BOOLEAN, Default True) — Статус активности счета.

#### `categories` (Категории расходов и доходов)
- `id` (INTEGER, PK, Auto-increment) — Уникальный ID категории.
- `name` (STRING) — Название категории (например, "Продукты", "Транспорт").
- `icon` (STRING) — Иконка эмодзи (например, "🛒", "🚕").
- `is_system` (BOOLEAN, Default True) — Флаг системной категории.

#### `mcc_mappings` (Сопоставление MCC-кодов)
- `mcc` (INTEGER, PK) — MCC-код продавца.
- `category_id` (INTEGER, FK -> categories.id) — Привязанная категория.
- `description_uk` (STRING, Nullable) — Описание MCC на украинском языке из `mcc-loc.json`.

#### `transactions` (Транзакции)
- `id` (STRING, PK) — Уникальный ID транзакции Monobank (защита от дублей).
- `user_id` (INTEGER, FK -> users.id) — Владелец.
- `account_id` (STRING, FK -> accounts.id) — ID счета.
- `time` (DATETIME) — Дата и время операции.
- `description` (STRING) — Описание платежа / название магазина.
- `amount` (INTEGER) — Сумма операции в копейках (>0 доход, <0 расход).
- `mcc` (INTEGER) — MCC-код операции.
- `balance` (INTEGER) — Остаток на счете в копейках после операции.
- `currency_code` (INTEGER) — Код валюты.
- `commission_rate` (INTEGER) — Комиссия в копейках.
- `cashback_amount` (INTEGER) — Кэшбэк в копейках.
- `comment` (STRING, Nullable) — Комментарий к платежу.
- `is_internal` (BOOLEAN, Default False) — Флаг внутреннего перевода (между своими счетами).
- `category_id` (INTEGER, FK -> categories.id, Nullable) — Привязанная категория.
- `created_at` (DATETIME, UTC) — Время добавления в БД.

## 4. Архитектура работы с Monobank API и Webhook

### 4.1. Ограничения по часовым интервалам (Rate Limiting)
- Monobank API ограничивает запросы к эндпоинтам `/personal/client-info` и `/personal/statement/{account}/{from}/{to}` — **не чаще 1 раза в 60 секунд** на один токен.
- Модуль `MonobankClient` управляетблокировками по токенам и отслеживает время последнего запроса, чтобы гарантировать соблюдение лимита в 60 секунд.

### 4.2. Обработчик Webhook (`POST /webhook/mono/{webhook_secret}`)
1. **Валидация (GET)**: Monobank проверяет эндпоинт отправкой `HTTP GET` запроса при установке вебхука. Сервер возвращает статус `HTTP 200 OK`.
2. **Обработка событий (POST)**:
   ```json
   {
     "type": "StatementItem",
     "data": {
       "account": "account_id",
       "statementItem": {
         "id": "trans_id",
         "time": 1700000000,
         "description": "Супермаркет",
         "mcc": 5411,
         "originalAmount": -15000,
         "amount": -15000,
         "currencyCode": 980,
         "commissionRate": 0,
         "cashbackAmount": 0,
         "balance": 500000,
         "hold": false
       }
     }
   }
   ```
3. **Этапы обработки**:
   - Проверка наличия `trans_id` в БД (защита от повторных уведомлений).
   - Определение категории по `mcc` из таблицы `mcc_mappings` (например, 5411 -> "Продукты 🛒").
   - Проверка на внутренний перевод (переводы между своими картами/банкой) -> удержание флага `is_internal = True`.
   - Сохранение транзакции в SQLite.
   - Отправка PUSH-уведомления в Telegram с Inline-кнопками для быстрой смены категории или переключения флага внутреннего перевода.

### 4.3. Ручная синхронизация выписки (`GET /personal/statement`)
- Запускается из меню бота по кнопке «🔄 Синхронизировать».
- Подгружает отсутствующие транзакции за выбранный интервал времени с учетом лимита запросов.

## 5. Правила категоризации и фильтрации транзакций

### 5.1. Автоматическая группировка MCC
- `5411`, `5499` -> **Продукты и супермаркеты 🛒**
- `5812`, `5814` -> **Кафе и рестораны 🍽️**
- `5541`, `5542` -> **Авто и АЗС ⛽**
- `4121`, `4111` -> **Транспорт и такси 🚕**
- `5912` -> **Аптеки и медицина 💊**
- `4814`, `4899` -> **Коммунальные услуги и связь 📱**
- Остальные MCC-коды сопоставляются с файлом `mcc-loc.json` либо относятся к категории **Другое 📦**.

### 5.2. Исключение внутренних переводов (`is_internal`)
- Транзакции с флагом `is_internal = True` исключаются из расчета совокупных доходов, расходов и чистого потока, чтобы не раздувать реальный финансовый оборот пользователя.

## 6. Модуль расчета финансовой аналитики

Генерирует отчеты за выбранный период (Сегодня, Неделя, Текущий месяц, Произвольный):
1. **Чистый финансовый поток (Cash Flow)**: $\text{Общий Доход} - \text{Общий Расход}$
2. **Совокупный доход (Total Income)**: Сумма всех `amount > 0` без учета `is_internal = True`.
3. **Совокупный расход (Total Expenses)**: Сумма всех $|amount|$ где `amount < 0` без учета `is_internal = True`.
4. **Анализ расходов по категориям**: Суммы в гривнах и процентное распределение по категориям.
5. **Среднесуточный расход**: $\frac{\text{Сумма расходов за текущий месяц}}{\text{Количество прошедших дней месяца}}$
6. **Текущий суммарный баланс**: Сумма доступных средств по всем счетам из `client-info`.

## 7. Пользовательский интерфейс Telegram-бота (UX)

### 7.1. Авторизация и доступ
- Бот проверяет Telegram ID входящего пользователя по значению `ADMIN_TELEGRAM_ID`. Для сторонних пользователей доступ блокируется.

### 7.2. Главное меню (Reply Keyboard)
- `👤 Профиль / Счета` -> Вывод балансов карт, банок, общей суммы активов.
- `📊 Финансовый отчет` -> Интерактивный выбор периода (Сегодня, Неделя, Месяц) -> формирование наглядного отчета.
- `🔄 Синхронизировать` -> Принудительное обновление выписки из Monobank.
- `⚙️ Настройки` -> Управление токеном, статус подключения Webhook.

### 7.3. Уведомления и Inline-кнопки
При поступлении новой транзакции через Webhook бот отправляет сообщение:
```text
💸 Новый расход!
Сумма: 250.00 ₴
Магазин: Сильпо
Категория: Продукты 🛒
Остаток: 12 450.00 ₴
```
Inline-кнопки под сообщением:
- `[ 🏷️ Изменить категорию ]` -> Вызывает меню выбора иной категории.
- `[ 🔄 Внутренний перевод: НЕТ ]` -> Переключает статус `is_internal`.

## 8. Безопасность и развертывание на Railway

1. **Переменные окружения (`.env`)**:
   - `BOT_TOKEN`: Токен Telegram-бота от @BotFather.
   - `ADMIN_TELEGRAM_ID`: Ваш Telegram ID.
   - `MONO_API_TOKEN`: Токен Monobank Personal API.
   - `WEBHOOK_BASE_URL`: Публичный URL приложения на Railway (например, `https://app.up.railway.app`).
   - `PORT`: Порт, предоставляемый Railway (по умолчанию 8080).
   - `DATABASE_URL`: `sqlite+aiosqlite:///data/finance_bot.db`

2. **Секретный эндпоинт Webhook**:
   - Формат пути: `/webhook/mono/{WEBHOOK_SECRET}`
   - Гарантирует невозможность отправки ложных данных посторонними лицами.

3. **Сохранность данных**:
   - Файл БД SQLite сохраняется в контейнере или монтируемом Volume (`/data/finance_bot.db`).
