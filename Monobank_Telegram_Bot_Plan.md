# План разработки Telegram-бота учета доходов и расходов на базе Monobank API

## 1\. Введение и архитектура

Данный документ содержит технический план по проектированию и разработке Telegram-бота для автоматического учета личных доходов и расходов с использованием **Monobank Personal API**.

Официальная документация Monobank API:

- [API документация Monobank](https://monobank.ua/api-docs)  
- [Monobank Open API for Providers](https://api.monobank.ua/docs/corporate.html)

---

## 2\. Поля данных транзакций (Схема БД)

Каждая транзакция, получаемая через Webhook или REST API `GET /personal/statement/{account}/{from}/{to}`, должна сохраняться в базе данных со следующей структурой параметров:

| Поле | Тип данных | Описание |
| :---- | :---- | :---- |
| `id` | String | Уникальный идентификатор транзакции (защита от дублирования). |
| `time` | Timestamp / Datetime | Дата и время проведения операции (конвертируется из Unix Timestamp). |
| `description` | String | Описание платежа (название магазина, назначение перевода, имя отправителя/получателя). |
| `amount` | Integer | Сумма операции в копейках. **\> 0** — Доход, **\< 0** — Расход. |
| `mcc` | Integer | Merchant Category Code (код сферы деятельности продавца). |
| `balance` | Integer | Остаток средств на счете в копейках после выполнения операции. |
| `currencyCode` | Integer | Код валюты (980 \= UAH, 840 \= USD, 978 \= EUR). |
| `commissionRate` | Integer | Комиссия за проведение операции (в копейках). |
| `cashbackAmount` | Integer | Начисленный кэшбэк (в копейках). |
| `comment` | String | Комментарий к платежу (если имеется). |
| `is_internal` | Boolean | Флаг внутреннего перевода (между своими картами/счетами/банками). |
| `category_id` | Integer / String | Привязанная пользовательская или авто-категория. |

## 3\. Логика обработки и категоризации транзакций

### 3.1. Категоризация по MCC-кодам

При получении транзакции автоматически сопоставлять `mcc` со справочником категорий:

- `5411`, `5499` — **Продукты и супермаркеты**  
- `5812`, `5814` — **Кафе, рестораны, фастфуд**  
- `5541`, `5542` — **Авто и АЗС**  
- `4121`, `4111` — **Транспорт и такси**  
- `5912` — **Аптеки и медицина**  
- `4814`, `4899` — **Коммунальные услуги и связь**

### 3.2. Фильтрация внутренних переводов

- Переводы между своими картами (например, с черной карты на белый счет или в «Банку») отображаются как параллельный расход и доход.  
- Такие операции помечаются как `is_internal = True` и **исключаются** из расчета общих доходов и расходов, чтобы не раздувать реальный финансовый оборот.

### 3.3. Ручная коррекция через Telegram-интерфейс

- К каждому PUSH-уведомлению от бота добавляются Inline-кнопки с выбором категории.  
- Пользователь может в один клик перекатегоризировать неопределенный P2P-перевод или покупку.

## 4\. Расчитываемые финансовые метрики

Бот должен уметь генерировать отчеты за любой выбранный период (день, неделя, месяц, год):

1. **Чистый финансовый поток (Cash Flow)**: $$\\text{Cash Flow} \= \\text{Общий Доход} \- \\text{Общий Расход}$$  
     
2. **Совокупный доход (Total Income)**:  
     
   - Сумма всех транзакций с `amount > 0` (без учета внутренних переводов и возвратов).

   

3. **Совокупный расход (Total Expenses)**:  
     
   - Сумма всех транзакций с `amount < 0` (без учета внутренних переводов).

   

4. **Анализ расходов по категориям**:  
     
   - Абсолютные суммы и процентное распределение трат по категориям.

   

5. **Текущий суммарный баланс**:  
     
   - Агрегированный баланс по всем счетам из метода `GET /personal/client-info`.

   

6. **Среднесуточный расход (Daily Average)**: $$\\text{Средний дневной расход} \= \\frac{\\text{Сумма расходов за текущий месяц}}{\\text{Количество прошедших дней месяца}}$$

---

## 5\. Ограничения и технические регламенты API Monobank

- **Rate Limit**: Запросы к эндпоинтам `GET /personal/client-info` и `GET /personal/statement` ограничены **1 запросом в 60 секунд** на токен.  
- **Webhook**: Для работы в реальном времени обязательна регистрация эндпоинта через `POST /personal/webhook`.  
- **Деноминация**: Все денежные показатели в API передаются в минимальных единицах (копейки). При выводе в интерфейс делить на 100 (`amount / 100.0`).
